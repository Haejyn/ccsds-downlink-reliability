# 요구사항 명세 — SpaceLink (CCSDS TM 다운링크 수신 처리)

> 지상국 영상수신처리 시스템의 첫 단계 — 위성이 보낸 전송 프레임을 검증하고 가상 채널별로 Space Packet 을 재조립한다.
> 기준 표준: CCSDS 132.0-B (TM Space Data Link Protocol), CCSDS 133.0-B (Space Packet Protocol).
> 시험 코드는 `[Trait("Requirement", "REQ-…")]` 로 요구사항을 가리킨다.

## 핵심 계약

> **손상됐을 가능성이 있는 패킷은 절대 내보내지 않는다. 손상과 무관한 패킷은 모두 복구한다.**
> 영상·텔레메트리 처리 체인의 뒷단은 수신기가 넘긴 패킷을 믿고 처리하므로, "조용한 손상"은 유실보다 나쁘다.

## 채널 부호·프레임 동기 (CCSDS 131.0-B 계열)

> 프레임 계층보다 앞단이다. 지금까지는 오류를 **검출만** 했고, 이 계층이 **정정**을 맡는다.
> RS 는 CCSDS 131.0-B-5 의 표준 부호다 — 생성 다항식의 근 `(α^11)^j, j = 112…143`(§4.3.4)과 이중 기저(dual basis, §4.3.9, 부속서 F) 변환을 부속서 G 의 계수표·부속서 F 의 변환 행렬과 값으로 대조했다(REQ-RS-01). 공개 구현 libfec 의 실제 출력과도 바이트 단위로 대조한다(REQ-RS-06). 실제 위성(Astrocast 0.1) 캡처의 비트열로도 ASM → PN → RS → 프레임 CRC 까지 복호한다(REQ-CAP-01).

| ID | 요구사항 | 판정 기준 |
|---|---|---|
| REQ-PN-01 | PN 랜덤화는 자기 역원이다. **옛 호환용 255 비트 수열**(§10.4.2)을 고를 수 있다 | 두 번 적용 = 원본 (무작위 길이 50 회), 수열 주기 255 바이트, **CCSDS 131.0-B-5 §10.4.3 NOTE 2 가 싣는 처음 40 비트 `FF 48 0E C0 9A` 와 일치**, 같은 다항식을 선형 점화식으로 쓴 독립 구현과 3 주기(765 바이트) 전량 일치 |
| REQ-PN-02 | **기본 PN 수열은 표준의 131071 비트 수열이다** — h(x) = x^17 + x^14 + 1, 초기값 `11000111000111000`, 코드블록마다 처음부터(§10.4.1·§10.4.3) | **표준이 싣는 처음 40 비트 `1C 71 B9 1B A9` 와 일치**(초기값 문자열의 오른쪽 끝이 첫 비트), 독립 구현(비트 배열 위의 점화식)과 쓸 수 있는 길이 전부(16,383 바이트) 일치, 주기 131071 비트, 최대 코드블록(2,040 바이트)에서 자기 역원. `ChannelCodec` 의 기본값이고, CADU = ASM + (RS 코드블록 ⊕ 고른 수열) |
| REQ-RS-01 | RS(255,223) 부호화·복호가 왕복한다. 생성 다항식·이중 기저 변환은 표준과 값으로 일치한다 | 인터리빙 1·2·3·4·5·8 에서 오류가 없으면 원본 그대로·정정 0 건. GF(256) 생성 다항식이 원시라 α 의 거듭제곱이 0 이 아닌 원소 255 개를 한 번씩 모두 훑는다. **생성 다항식 계수 32 개가 CCSDS 131.0-B-5 부속서 G 의 표와 정확히 일치**(값 대조). 이중 기저 변환은 부속서 F 의 행렬로 왕복(256 개 값 전부)하고 두 예시 행과 값으로 일치 |
| REQ-RS-02 | 부호어당 심볼 오류 16 개까지 정정한다 | t = 0 … 16 × 시드 5 개 — 전부 성공, 정정한 심볼 수 = 주입한 수, 데이터가 원본과 일치 |
| REQ-RS-03 | 정정 능력을 넘으면 **실패를 선언한다**. 오정정이 나는 경우에는 프레임 CRC 가 2차 방어선이 된다 | t = 17·18·20·24·32 × 600 회 = 3,000 회 — **전부 실패 선언, 오정정 0 건**. 오정정이 한 번도 관측되지 않았으므로 **CRC 방어선은 이 시험으로 확인된 것이 아니다** (관측되면 잡도록 단언을 걸어 둔다) |
| REQ-RS-04 | 인터리빙이 버스트 오류를 부호어들로 나눈다 | 깊이 I 에서 연속 I·16 심볼 버스트를 정정한다. 같은 버스트를 깊이 1 로 받으면 원본 복원에 실패한다 |
| REQ-RS-05 | 223·I 바이트보다 짧은 프레임은 **짧은 코드블록**으로 보낸다 — 코드블록 앞쪽 Q 심볼(가상 채움, I 의 배수)을 0 으로 쳐서 계산하고 **보내지 않는다**(§4.3.7). 정정 위치가 채움 자리로 나오면 실패로 알린다 | 짧은 코드블록 = 앞에 0 을 Q 개 붙여 전체 길이로 부호화한 부호어에서 그 Q 개를 뗀 것(I = 1·4·5, 프레임 1·125·128 B). 128 B 프레임의 CADU 164 B(ASM 4 + 128 + 체크 32). 부호어당 심볼 오류 16 개 정정 유지(I = 1·4). 채움 자리와 거리 1 인 부호어로 가는 수신어는 실패 선언. Q 가 I 의 배수가 아니면 거부 |
| REQ-RS-06 | 부호화·복호가 **독립 구현(libfec 의 CCSDS RS)** 과 일치한다. 정정 위치가 가상 채움 자리로 나오는 경우만 **의도적으로 더 엄격하다** | `tests/SpaceLink.Tests/golden/libfec_rs_vectors.txt`(`tools/gen_golden_libfec.py`, libfec 고정 커밋) — 부호화 35 개(가상 채움 Q = 0·1·95·100·222)가 **바이트 단위 일치**, 복호 25 개(오류 0·1·8·16·17)가 성공·실패 판정과 정정 수·복호 결과까지 일치. 채움 자리 정정은 libfec 가 "성공" 으로 손상 데이터를 내보내는 경우라 이 구현은 실패로 알린다. CI 가 벡터를 다시 만들어 대조한다 |
| REQ-RS-07 | 인터리빙 깊이는 **표준이 허용하는 값만** 받는다 — I = 1, 2, 3, 4, 5, 8 (§4.3.5.1) | `ReedSolomonCodec` · `ChannelCodec` 두 생성자 모두 −1·0·6·7·9·16 을 `ArgumentOutOfRangeException` 으로 거부(거부한 값을 예외에 담는다), 허용 여섯 값은 받아 코드블록 255·I 바이트. 여섯 값 전부 부호화·복호 왕복(REQ-RS-01), 깊이 2·4·5·8 에서 I·16 심볼 버스트 정정(REQ-RS-04) |
| REQ-CAP-01 | **실제 위성이 보낸 비트열**을 수신 체인 전체로 복호한다 — ASM 동기 → PN 되돌림 → RS 복호(인터리빙·이중 기저) → 전송 프레임 검증 | Astrocast 0.1(NORAD 43798) 9k6 FSK 녹음(DK3WN, gr-satellites 의 satellite-recordings, Unlicense)을 `tools/gen_golden_capture.py` 로 복조한 비트열(`golden/astrocast_9k6_bits.bin`) — CADU 3 장 전부 동기·RS 성공(I = 5, PN 255 비트), **송신기가 계산한 프레임 CRC-16 이 맞고** SCID 1 · VC 4 · 마스터 프레임 카운트 0x17·0x18·0x19 연속. 다른 PN 수열로는 3 장 모두 실패. 실제 코드블록에 레인마다 심볼 오류 16 개 → 원래 프레임 복원(정정 80), 17 개 → 실패.
